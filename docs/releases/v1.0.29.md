# Release v1.0.29 — Single Native Video Speaker Control & Multi-Layer Anti-Buffering Engine

- **Clean Video Overlay (`index.html`):**
  - Removed the duplicate custom top-right `.video-mute-btn` overlay so video posts show only the single built-in speaker control inside the bottom player bar without obstructing upper-right video captions.
- **Native HTTP/2 Head Prefetch & Disk Range Proxy (`VideoStreamProxy.kt`, `MainActivity.kt`, `TwitterBridge.kt`, `XLitePolicy.kt`):**
  - Added `VideoStreamProxy` (`cacheDir/videos`, 64 MB disk budget) and `@JavascriptInterface prefetchVideo(url)` using OkHttp's shared HTTP/2 connection pool to prefetch the opening `768 KB` (`moov` metadata + initial video frames) for active and upcoming videos before you scroll to them.
  - Added `https://local.xlite/vid?url=...` RFC 7233 `206 Partial Content` interception in `MainActivity.kt` so cached opening frames begin playing from disk at `0 ms` while tail segments stream over warm HTTP/2 connections (backward-compatible with older APKs via `supportsVideoProxyNative()`).
- **Adaptive Bitrate & Stall Auto-Recovery (`index.html`):**
  - Added `chooseVideoStreams` to prefer crisp `<= 2.6 Mbps` 720p mobile HD on cellular links instead of choking on oversized `5–12+ Mbps` progressive 1080p60 MP4s, while preserving highest-bitrate playback on Wi-Fi.
  - Added `attachVideoBufferingMonitor` so continuous playback stalls/buffering (`>= 2.2s`) automatically step down to a faster fallback stream preserving current timestamp.
  - Expanded look-ahead prebuffering (`900px` `rootMargin` with `MAX_AUTO_PRELOADS = 2` decoder budget + `<link rel="preconnect" href="https://video.twimg.com">`) so nearby videos buffer smoothly without exhausting Android hardware `MediaCodec` decoders.
