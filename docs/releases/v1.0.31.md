# Release v1.0.31 — HTTP/1.1 Loopback Range Proxy (`127.0.0.1`), Instant Video Playback & Direct HTTPS Fallback

- **Fixed Video Playback Regression from `v1.0.29` (`VideoStreamProxy.kt`, `MainActivity.kt`, `TwitterBridge.kt`):**
  - Replaced `WebViewClient.shouldInterceptRequest` (`https://local.xlite/vid`) interception with a real embedded HTTP/1.1 `127.0.0.1` loopback Range streaming server (`VideoStreamProxy.getProxyPort()` + `@JavascriptInterface getVideoProxyPort()`).
  - Eliminates Chromium `AndroidStreamReaderURLLoader` double-skipping of `206 Partial Content` `InputStream`s, which had stalled metadata loading (`0:00` with missing duration) and video playback on Android devices.
  - Streams `1 MB` prebuffered disk head chunks (`moov` atom + opening GOP frames) immediately over real TCP sockets, opportunistically tees uncached `bytes=0-` reads into disk cache for zero-cost loops/replays, and handles `GET`/`HEAD`/`200`/`206`/`416` cleanly with strict `XLitePolicy.isAllowedVideoUrl` (`https://video.twimg.com/...`) enforcement.
- **Scoped Loopback Network Security Config (`network_security_config.xml`, `AndroidManifest.xml`):**
  - Configured `<base-config cleartextTrafficPermitted="false" />` and `android:usesCleartextTraffic="false"` globally while permitting loopback HTTP strictly for `127.0.0.1` (`includeSubdomains="false"`).
- **Backward-Compatible OTA Fix & Resilient Direct HTTPS Fallback (`index.html`):**
  - `localVideoUrl()` routes through `http://127.0.0.1:<port>/vid?url=...` only when the installed APK exposes `AndroidBridge.getVideoProxyPort()`, restoring direct `https://video.twimg.com/...` streaming immediately on `v1.0.29` / `v1.0.30` APKs updated over-the-air.
  - Added direct `https://video.twimg.com/...` tail fallback alongside bitrate downgrade (`1.8s` stall watchdog + `vid.load()` recovery), eager `preload="metadata"` for immediate duration display, and 3-ahead video prefetching.
