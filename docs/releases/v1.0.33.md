# Release v1.0.33 — Multi-Hop Navigation Back Stack, Drift-Free Scroll Preservation & Video Playback Stability

- **Unified Multi-Hop History Stack & Chrome Synchronization (`index.html`):**
  - Replaced single-slot back handling with `viewHistoryStack` + `pushHistorySnapshot` / `restoreViewSnapshot` across Feed, Thread, Profile, Notifications, Search, Post, and Settings, pushing real history entries on `openProfile`, `nav`, and `openLightbox` so Android hardware Back cleanly unwinds intermediate screens without skipping views or exiting the app.
  - Updated `←` header buttons across Profile, Notifications, and Settings to use `goBackToFeed()` and unified `syncChromeForView` / `onpopstate` to restore `.in-feed`, `#tabNav`, search input focus blur, and the scroll-to-top button at every hop.
  - Made `openLightbox` push a dedicated `{ view: 'lightbox' }` entry and close in place on `history.back()` without popping or corrupting the underlying view snapshot; invalidated cached Feed frames in both `savedFeedNodes` and `viewHistoryStack` (`invalidateSavedFeed`, `savedFeedCacheDirty`) on live Settings changes or Offline bookmark updates.
- **Scroll Anchor Resilience & Non-Destructive Paging (`index.html`):**
  - Preserved `Offline` (`cache`) DOM across navigation unless dirtied by bookmark changes (`savedFeedCacheDirty`), prevented Profile (`openProfile`) / Alerts (`Notifications`) navigation from discarding `savedFeedNodes` (`loadFeed('foryou')` reloading past `seenForYouIds`), and preserved existing DOM nodes during `fetchProfileTimeline` pagination (`insertAdjacentHTML` into `#profileFeedBox`) and `fetchSearchPage` video observation.
  - Temporarily disabled `overflow-anchor` during scroll restoration, added fallback aspect-ratio layout reservations (`aspect-ratio: 16 / 9` on `.tweet-video` and `.link-card-img`, plus `'tap'` image `data-aspect`), and added `ResizeObserver` + capture-phase media listeners through layout settle (up to `2400ms`, still cancelled immediately on user input).
- **Video Decoder Budget & Native `VideoStreamProxy` Hardening (`VideoStreamProxy.kt`, `index.html`):**
  - Replaced `SynchronousQueue` in `VideoStreamProxy.kt` with a bounded `ThreadPoolExecutor` + `LinkedBlockingQueue(128)` so parallel video/seek/metadata sockets no longer suffer `503` executor rejections.
  - Committed the 1 MiB `.head` + `.meta` cache immediately upon reaching `targetHeadBytes` before waiting on full stream EOF, swept stale `.tmp` artifacts on startup, and threw `IOException` on non-2xx/206 or truncated upstream tails.
  - Reclaimed off-screen paused `<video>` elements (`>4` cards away with `currentTime === 0`) via `reclaimDistantVideos` (`preload = 'none'`, stashing `dataset.xliteParkedSrc`, clearing `src` + `load()`) to keep Chromium `MediaCodec` pipelines free and restored `src` seamlessly on scroll back (`restoreParkedVideo`).
- **Verification & Regression Coverage (`scripts/chrome-e2e.test.cjs`, `scripts/feed-media.test.cjs`, `XLiteUnitTest.kt`):**
  - Added real `360x800` headless Chrome CDP end-to-end suite (`11` scenarios) plus expanded Node VM and JUnit4 loopback proxy regression tests covering multi-hop Back, Lightbox Back, delayed media scroll stability, append-only paging, decoder parking, early head-cache commit, tail failure truncation, and concurrent bursts.
